# ストリーミング実装の分析と改善提案

## 現状の評価

### ✅ 正しく実装されている点

| 項目           | 状態 | 説明                                                                           |
| -------------- | ---- | ------------------------------------------------------------------------------ |
| API ルート     | ◎    | `streamText` + `toUIMessageStreamResponse` で UIMessage ストリームを返している |
| Edge Runtime   | ◎    | 低レイテンシでストリーミング応答                                               |
| useChat        | ◎    | `DefaultChatTransport` でストリーミング受信                                    |
| テキスト表示   | ◎    | `part.text` はストリームに応じて逐次更新される（useChat の仕様）               |
| ツール UI      | ◎    | `input-available` → Skeleton、`output-available` → 実コンポーネント            |
| アニメーション | ◎    | CardGrid / BarChart / Timeline など framer-motion で入場アニメーション         |

### ⚠️ 活用しきれていない点

| 項目                     | 現状          | 改善余地                                                                                                |
| ------------------------ | ------------- | ------------------------------------------------------------------------------------------------------- |
| **input-streaming**      | 未対応        | AI がツール引数を生成中（`state: "input-streaming"`）の段階を無視。`input-available` まで Skeleton のみ |
| **output-error**         | 未対応        | ツール実行エラー時（`state: "output-error"`）の表示がない                                               |
| **自動スクロール**       | なし          | ストリーミング中に新コンテンツが下部に追加されても、自動でスクロールされない                            |
| **テキスト編集カーソル** | なし          | テキストが途中まで表示されているときの「入力中」感が弱い                                                |
| **ツール別ローディング** | 汎用 Skeleton | 全ツールで同じ Skeleton。ツール種別ごとのメッセージ（例: カード生成中…）でUX向上可能                    |

---

## 改善提案（優先度順）

### 1. input-streaming 対応（高）

AI SDK 5.0 以降、ツール呼び出しの引数はストリーミングで送られる。`state: "input-streaming"` のとき `part.input` に部分的な引数（DeepPartial）が入る。

**提案**: 部分的な `input` を使って、プレビュー表示や「生成中…」のようなツール種別メッセージを表示する。

### 2. output-error ハンドリング（高）

ツール実行失敗時は `state: "output-error"`、`part.errorText` にエラーメッセージが入る。

**提案**: エラー時に `errorText` を表示し、ユーザーに状況を伝える。

### 3. ストリーミング中の自動スクロール（中）

新しいメッセージやツール結果が追加されると、表示領域の下端にコンテンツが入る。ユーザーが手動でスクロールしないと見えない。

**提案**: `status === "streaming"` のとき、または最後のメッセージに対応する ref を監視し、`scrollIntoView({ behavior: "smooth" })` で最新コンテンツへスクロールする。

### 4. テキストストリーミング時のカーソル表示（中）

テキストが途中まで表示されているとき、「まだ入力中」であることが分かりづらい。

**提案**: 最後のアシスタントメッセージの最後のテキスト part に、`status === "streaming"` のときだけ点滅カーソル（`|`）を付ける。

### 5. ツール別ローディング表示（低）

すべてのツールで同じ Skeleton を使っている。

**提案**: ツール名（showCards, showChart など）に応じて「カードを生成中…」「チャートを生成中…」などの文言を表示する。

## 技術メモ

- **ToolUIPart の state**:
  - `input-streaming`: 引数ストリーミング中（`input` は DeepPartial）
  - `input-available`: 引数確定、実行待ち
  - `output-available`: 実行完了、結果あり
  - `output-error`: 実行失敗、`errorText` あり

- **useChat の messages**: ストリームに応じてリアルタイムで更新される。テキスト part は `part.text` が徐々に伸びていく。
